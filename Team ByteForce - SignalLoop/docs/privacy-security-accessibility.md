# Privacy, Security, and Accessibility

## Privacy

- Collect only information needed to triage and resolve an incident.
- Explain who can see reports and attachments before submission.
- Avoid exposing reporter identity or contact details to unauthorized users.
- Use fictional or anonymized records in demos and screenshots.
- Define retention, export, and deletion procedures with the institution.
- Obtain appropriate consent before recording voice or uploading identifying images.

## Security

- Enforce permissions on the backend.
- Never commit API keys, passwords, tokens, or production credentials.
- Protect attachments with authorization checks.
- Validate and sanitize user input and file uploads.
- Use secure authentication and session management.
- Keep dependencies updated and review security advisories.
- Audit sensitive actions such as reassignment, priority changes, and closure.

## AI Transparency

- Label AI-generated suggestions clearly.
- Let authorized users review and edit suggestions.
- Do not use AI alone for disciplinary, safety-critical, or other high-impact decisions.
- Provide a manual path when AI is unavailable.
- Test for errors and bias using representative, appropriately governed data.

## Accessibility

- Use semantic headings and form labels.
- Ensure keyboard access and visible focus indicators.
- Provide text labels in addition to color or icons.
- Check contrast for text, controls, and status badges.
- Announce form errors and meaningful status updates accessibly.
- Support zoom and responsive layouts.
- Keep language simple; consider Nigerian Pidgin as an optional language mode.
- Make voice input optional and allow transcript correction.

## Emergency Disclaimer

Do not represent SignalLoop as an emergency response service unless an institution has explicitly established, staffed, and tested that capability. Show appropriate campus emergency contacts where required.
